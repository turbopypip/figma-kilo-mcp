# Figma MCP для Kilo Code

## Цель

Создать локальный MCP-сервер и плагин Figma, позволяющие ИИ-агенту в Kilo Code получать данные выбранного макета и использовать их для вёрстки в существующем проекте.

## Главное бизнес-требование

**Решение должно потреблять минимальное количество ресурсов ПК на Windows.**

Это основной критерий архитектурных решений. При равной функциональности выбирать вариант с меньшим потреблением RAM, CPU, диска и меньшим числом фоновых процессов. Удобство разработки не должно оправдывать тяжёлую инфраструктуру.

- Основная платформа — Windows 10/11 x64, без обязательных WSL, Docker и прав администратора.
- Не запускать отдельный браузер, Electron-приложение, локальную LLM, базу данных или постоянно работающую службу.
- Один процесс MCP-сервера; локальное соединение с плагином обслуживается этим же процессом.
- Не выполнять постоянный опрос Figma, сканирование проекта или обработку всего документа в фоне.
- Читать и преобразовывать данные по запросу агента. События соединения и выделения обрабатывать без дорогостоящего пересчёта дерева.
- Экспортировать изображения только по запросу, с ограничением разрешения и размера результата.
- Ограничить объём кеша, размер сообщений и число одновременных тяжёлых операций. Освобождать временные данные после завершения запроса или отключения.
- Использовать минимальный набор зависимостей. Для работы установленного сервера не нужны сборщик, TypeScript watch и другие процессы разработки.
- Завершать сервер и освобождать соединения при закрытии MCP-сессии Kilo Code.

### Проверка потребления ресурсов

Приведённые ниже числа — начальные инженерные ориентиры, а не уже измеренные показатели. Их нужно проверить на Windows и уточнить по результатам прототипа, сохраняя минимальное потребление ресурсов главным требованием.

- Простой: средняя загрузка CPU процессом сервера не более 1% за 60 секунд, память процесса ориентировочно до 100 МиБ.
- После серии запросов потребление памяти стабилизируется; отсутствуют непрерывный рост памяти и накопление временных файлов.
- В простое отсутствуют периодические запросы к Figma и вычисления по макету.
- Для чтения структуры и экспорта изображений измерять время, пиковую память и CPU отдельно; фиксировать размер тестового фрейма и параметры изображения.
- Указывать конфигурацию ПК, версию Windows и Node.js, способ измерения. Отдельно учитывать сервер и дополнительную нагрузку плагина на Figma; базовое потребление Figma и Kilo Code не включать в бюджет сервера.
- Большие запросы должны ограничиваться или завершаться понятной ошибкой, а не приводить к зависанию ПК.

## Архитектура

```text
Открытый документ Figma
        ↕ Plugin API
Плагин Figma
        ↕ локальное соединение
MCP-сервер (Node.js / TypeScript)
        ↕ stdio
Kilo Code
```

- Плагин читает документ через Figma Plugin API. Основной сценарий не использует Figma REST API и не требует REST-токена.
- Плагин и документ должны быть открыты во время запросов к макету. При отсутствии плагина сервер сообщает, как восстановить соединение.
- Локальный транспорт между плагином и сервером выбрать при реализации с учётом ограничений Plugin API и требований к ресурсам; избегать периодического опроса.
- Подключение Kilo Code — через стандартный MCP поверх stdio. Диагностика выводится в stderr и не повреждает протокольный stdout.
- MCP предоставляет данные для вёрстки; генерацию кода и работу с репозиторием выполняет агент Kilo Code.

## Основной пользовательский сценарий

1. Пользователь устанавливает сервер и подключает его в Kilo Code.
2. Открывает макет в Figma, запускает плагин и выделяет фрейм.
3. Просит Kilo Code сверстать выделенный экран с использованием компонентов текущего проекта.
4. Агент получает структуру, визуальный образец и необходимые ассеты через MCP.
5. После изменения макета агент может повторно запросить актуальные данные.

## Инструменты первой версии

| Инструмент | Назначение |
| --- | --- |
| `get_selection` | Вернуть идентификаторы, типы и названия выделенных узлов без полного дерева документа. |
| `get_design_context` | Вернуть компактное структурированное описание выбранного узла или узла по ID. |
| `get_screenshot` | Экспортировать PNG выбранного фрейма с ограничением масштаба и размера. |
| `export_assets` | Экспортировать запрошенные иконки и изображения в разрешённую локальную папку. |

Для больших деревьев предусмотреть ограничение глубины и количества узлов, явный признак сокращения результата и возможность отдельно запросить дочерний узел. Не выдавать неполные данные за полный макет.

## Данные для вёрстки

- Идентификаторы, типы, названия, иерархия и видимость элементов.
- Размеры, координаты и правила изменения размеров.
- Auto Layout: направление, gap, padding, выравнивание, переносы и режимы размеров, если доступны.
- Текст и стили отдельных диапазонов: шрифт, размер, начертание, межстрочное и межбуквенное расстояние.
- Заливки, обводки, скругления, прозрачность и эффекты.
- Компоненты, экземпляры, варианты и свойства в пределах доступных данных Plugin API.
- Доступные привязки стилей и переменных; недоступные значения обозначать явно.
- Ссылки между элементами и экспортированными ассетами.

Сохранять значимые для внешнего вида сведения, убирая технический шум и повторы. Не выдумывать адаптивные правила, поведение интерфейса и соответствия компонентам проекта, которых нет в исходных данных.

## Локальность и безопасность

- Сервер слушает только loopback-интерфейс, а не всю локальную сеть.
- Соединение плагина с сервером защищено проверкой сессионного секрета или эквивалентным механизмом; одного CORS недостаточно.
- Плагин запрашивает только необходимые сетевые разрешения.
- Сервер и плагин не отправляют макет сторонним сервисам и не содержат телеметрии. Данные, переданные Kilo Code, далее обрабатываются согласно настройкам выбранной пользователем модели.
- Запись ассетов ограничена явно настроенной папкой. Защита от выхода за её пределы, коллизий имён и неявной перезаписи файлов.
- Первая версия только читает макет и экспортирует данные; не изменяет документ Figma.

## Надёжность и совместимость

- Обрабатывать отсутствие выделения, закрытие плагина, удалённый узел, недоступные свойства, обрыв соединения и конфликт локального порта.
- У запросов есть таймауты; отмена запроса освобождает связанные ресурсы, насколько это позволяет Plugin API.
- Повторное подключение не создаёт дублирующих процессов, обработчиков или очередей.
- Работать с путями Windows, включая пробелы и кириллицу.
- Документировать минимальную поддерживаемую версию Node.js и проверенную версию Kilo Code; пример конфигурации должен соответствовать этой версии.
- Кеш, если используется, имеет предел размера и механизм обновления после изменений макета. Не возвращать устаревшие данные как актуальные.

## Результат первой версии

- Исходники плагина Figma и MCP-сервера.
- Команды установки, сборки и запуска на Windows.
- Пример настройки MCP в Kilo Code без секретов в репозитории.
- Инструкция по загрузке плагина и прохождению основного сценария.
- Проверка получения контекста, PNG и ассетов через Kilo Code на реальном фрейме.
- Проверка отключения, повторного подключения, ограничений больших запросов и безопасной записи файлов.
- Краткий отчёт об измеренном потреблении ресурсов на Windows в простое и под нагрузкой.

## За пределами первой версии

- Парсинг внутреннего формата `.fig` или DOM сайта Figma.
- Собственный редактор, отдельный графический интерфейс сервера и облачный сервис.
- Автоматическое изменение макета, фоновая синхронизация всего документа и индексация всех файлов проекта.
- Гарантия автоматической вёрстки без ошибок: качество реализации зависит от агента, модели, структуры макета и требований проекта.
