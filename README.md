# Figma MCP для Kilo Code CLI

Локальный MCP-сервер для чтения макетов и реализации их в коде. Пользователь входит в нужный аккаунт в **Figma Desktop**, открывает документ, запускает плагин и выделяет фрейм. Плагин передаёт данные агенту через локальный сервер.

**Без Figma REST API, REST-токена и его квот.** Используется встроенный Figma Plugin API в открытом документе. Сервер не входит в аккаунт, не хранит пароль и не запускает браузер. Доступ к документам определяется аккаунтом в Figma. Ограничения Figma и самой выбранной модели этим проектом не отменяются.

Стек: Node.js, TypeScript, официальный MCP SDK 2.3.1, `ws`, `zod`; esbuild только для сборки плагина. Один процесс сервера, без опроса документа, кеша макетов, базы данных и телеметрии. Документ не изменяется. Данные, полученные Kilo, обрабатываются выбранной в Kilo моделью.

## Нужны ли Desktop и подписка?

**Для текущей версии нужен Figma Desktop:** плагин подключается локально через Import plugin from manifest, а разработка и тестирование локальных плагинов поддерживаются в Desktop. Веб-версия Figma умеет запускать опубликованные плагины, но текущий мост не опубликован; его localhost-доступ сейчас указан только в `devAllowedDomains`. Поэтому просто открыть этот проект в браузере недостаточно. Для веб-варианта понадобятся публикация плагина, настройка разрешений production-сети и отдельная проверка подключения браузера к loopback.

**Платная подписка не обязательна:** Figma разрешает запуск Figma Design plugins на бесплатном Starter. В платных рабочих пространствах для Design plugins таблица Figma указывает Full seat; Dev/Collab/View не подходят для текущего `editorType: ["figma"]`. Организация также может запрещать неутверждённые плагины. Отдельно нужны права на работу с конкретным файлом. Этот сервер не использует платный Dev Mode или официальный Figma MCP.

Источники: [Figma Plugin Quickstart](https://developers.figma.com/docs/plugins/plugin-quickstart-guide/), [Use plugins in files — планы и seats](https://help.figma.com/hc/en-us/articles/360042532714-Use-plugins-in-files), [сетевые разрешения manifest](https://developers.figma.com/docs/plugins/manifest/).

## Установка на Windows

Нужны Node.js **20.12+** (для новой установки рекомендуется актуальная LTS 22/24), npm и Figma Desktop. Kilo CLI проверен на версии **7.8.12**: команда `kilo mcp list` успешно подключила сервер. WSL, Docker и права администратора не требуются.

В PowerShell из папки проекта:

```powershell
npm ci
npm run check
npm test
npm run setup -- --assets "C:\Users\User\Проект\public\figma"
```

`npm test` также собирает сервер и плагин. Для пересборки отдельно: `npm run build`. Укажите свою **абсолютную** папку для ассетов. Пробелы и кириллица поддерживаются; ассеты не пишутся в другие папки.

Setup создаёт игнорируемую Git папку `.local`:

- `config.json` — секрет, порт и разрешённая папка экспорта;
- `pairing.txt` — секрет для вставки в плагин;
- `kilo.json` — готовая конфигурация с абсолютными путями и текущим Node.js.

Секрет не печатается в логи. На Windows файлы используют права текущей папки пользователя: храните проект в своей учётной записи. Повторный setup сохраняет секрет; смена папки экспорта требует явного редактирования `.local/config.json`.

Объедините поле `mcp.figma` из `.local/kilo.json` с конфигурацией Kilo своего проекта (`kilo.json`). Не заменяйте остальные настройки. Пример без секретов: [`examples/kilo.json`](examples/kilo.json). В Kilo используется `mcp`, `type: "local"`, массив `command` и `environment`; формат настроек расширения VS Code здесь не подходит.

```powershell
kilo mcp list
```

Ожидаемый результат — `figma connected`. Это подтверждает соединение **Kilo → MCP**, а не наличие открытого плагина. После проверки запустите обычную сессию Kilo: сервер работает только пока открыт MCP-клиент. Не запускайте параллельно `npm start` и Kilo для одной конфигурации.

После сборки можно выполнить `npm prune --omit=dev`: для работы нужен только `node dist/index.js`. Для разработки и повторной сборки верните зависимости через `npm ci`.

## Подключение Figma

1. Откройте Figma Desktop и войдите в нужный аккаунт обычным способом.
2. Откройте документ с макетом.
3. Выберите **Plugins → Development → Import plugin from manifest…**, укажите `plugin/manifest.json` этого проекта. Файлы `code.js` и `ui.html` создаются сборкой рядом с manifest.
4. Запустите **Figma Kilo Bridge** из меню Development.
5. Откройте `.local/pairing.txt` локальным редактором, вставьте секрет в поле плагина и нажмите «Подключить». Не вставляйте секрет в чат с моделью.
6. Выделите один фрейм. Плагин должен оставаться открытым во время работы.

В manifest используется локальный ID плагина. Для публикации или если Figma требует выданный ID создайте development plugin в Figma и замените `id` значением из его manifest; остальные поля оставьте как в проекте. Публикация не нужна для основного сценария.

Пример запроса в Kilo:

> Через figma MCP прочитай выделенный экран, получи контекст и скриншот. Экспортируй нужные иконки, затем реализуй экран в текущем проекте, переиспользуя существующие компоненты. Если дерево сокращено, запроси нужные дочерние узлы отдельно. Не выдумывай адаптивное поведение, которого нет в макете.

## Инструменты

| Инструмент | Параметры | Результат |
| --- | --- | --- |
| `get_selection` | нет | ID, типы, названия выделения и текущая страница |
| `get_design_context` | `nodeId?`, `depth=4`, `maxNodes=200` | дерево, геометрия, Auto Layout, текстовые диапазоны, заливки, обводки, эффекты, компоненты, привязки |
| `get_screenshot` | `nodeId?`, `scale=1` | PNG как MCP image, ID и фактически применённый масштаб |
| `export_assets` | `nodeIds`, `format=PNG`, `scale=1` | локальные пути PNG/SVG, размеры в байтах и ID исходных узлов |

Без `nodeId` нужно выделить ровно один элемент. Обращение по ID может загрузить соответствующую страницу через Plugin API. Данные читаются заново при каждом вызове. Координаты `x/y` относятся к родителю; `absoluteBoundingBox` — к документу. Значения variables и определения styles отдельно не загружаются: возвращаются привязки и применённые свойства, а недоступность определений обозначается явно. Соответствие компонентам кодовой базы определяет агент.

Экспорт ассета — экспорт указанного **узла**, не скачивание оригинального файла заливки. SVG сохраняет векторные данные; PNG имеет ограничение разрешения. Результаты частичного пакетного экспорта остаются на диске, ошибки указаны по каждому ID. Повторный экспорт создаёт новый файл.

## Технические ограничения

Квот на количество обращений нет. Ограничения ниже защищают память и интерфейс; согласованы отдельно от отсутствия REST-квот:

- Один выполняемый запрос плагина, один пакет экспорта; вместо накопления очереди возвращается `busy`.
- Контекст: максимум 500 узлов, глубина 12, до 800 000 символов свойств, до 100 000 символов на узел, текст до 8000 символов. Выделение — до 500 элементов.
- Сокращение дерева отмечается `truncated`, `truncations`, `childrenTruncated`, `childCount`, `nextChildId`. Запрашивайте дочерний ID отдельно; отдельный чрезмерно большой узел тоже может оставаться сокращённым.
- PNG: масштаб 0.1–2, длинная сторона до 2048 px, файл до 3 МиБ. SVG тоже до 3 МиБ. Перед экспортом проверяются 1000 узлов и глубина 64. Native `exportAsync` всё равно может временно потребовать память внутри Figma до проверки размера готового файла.
- До 10 ID в одном `export_assets`, последовательная обработка. Сообщения WebSocket — до 6 МиБ.
- Таймаут одного обращения 30 секунд. При отмене/таймауте соединение разрывается и освобождается ожидание сервера. Figma не позволяет прервать уже начатый `exportAsync`: до его завершения плагин остаётся занят. После ошибки подключитесь снова кнопкой.

## Безопасность и восстановление

Сервер слушает только `127.0.0.1:3055`, проверяет случайный 256-битный секрет и принимает один плагин. Постороннее соединение не заменяет действующее. Секрет не передаётся в URL и не доступен инструментам агента. Нет автоматического переподключения или фонового опроса. Состояние выделения читается по запросу.

Папка ассетов определяется при запуске; агент не выбирает произвольный путь. Имена плоские, с безопасным префиксом и UUID, создание эксклюзивное без перезаписи. Папка канонизируется; подмена симлинком обнаруживается. Локальный злоумышленник с правами записи в родительскую папку находится вне модели защиты: не размещайте экспорт в общей изменяемой папке.

При закрытии stdio-сессии сервер закрывает WebSocket и завершается. Если порт занят, завершите другую сессию MCP. Для другого порта нужно согласованно изменить `.local/config.json`, адрес в `plugin/ui-source.html`, `devAllowedDomains` в manifest и пересобрать плагин. Для нескольких параллельных проектов используйте отдельные порты/копии плагина.

## Проверки и измерения

```powershell
npm run check
npm test
npm run measure
```

Тесты запускают настоящий MCP-клиент и отдельный процесс сервера. Плагин выполняется из собранного `code.js` с подменённым Figma API. Проверяются контекст, PNG/SVG, пути с кириллицей, секрет, отсутствие/разрыв соединения, busy, отмена, таймаут, переподключение и завершение процесса. Проверка UI использует DOM/WebSocket-заглушки, поэтому не проверяет реальный CSP Figma. CI настроен на Windows, macOS и Linux; сам по себе файл CI не означает, что Windows-прогон уже выполнен.

`npm run measure` измеряет отдельный процесс сервера: 60 секунд простоя без запросов к плагину, затем три серии по 20 запросов с подменённым Figma API. Отчёт: `artifacts/resources-mock.json`. Для реального макета на Windows:

```powershell
# Закройте Kilo, чтобы освободить порт. Настройка npm run setup должна быть выполнена.
npm run measure -- --real
# Подключите плагин, выделите фрейм и нажмите Enter в терминале.
```

Отчёт: `artifacts/resources-real.json`. Режим `--real` выполняет настоящее чтение и PNG-экспорт, но не пишет ассеты. Замеры используют `process.cpuUsage`, `memoryUsage` и `resourceUsage` в процессе сервера, через отдельный IPC listener только на время benchmark. Пик RSS накопительный за жизнь процесса; результаты трёх серий не доказывают отсутствие утечки на длинных нагрузках. Дополнительную память/CPU плагина Figma нужно измерить отдельно средствами Windows. Подробный статус проверки — [`TEST_REPORT.md`](TEST_REPORT.md).
